# Subaru ECU Editor

Десктопный редактор калибровочных карт прошивок (ROM) ЭБУ Subaru на Python + PyQt6.
По описаниям RomRaider (`ecu_defs.xml`) определяет ЭБУ в образе, находит карты (наддув,
топливо, зажигание…) и показывает их таблицей и графиком в физических единицах. Есть свой
логгер через Tactrix OpenPort 2.0 и MCP-сервер для работы с ИИ.

> Статус: ранняя стадия. Чтение и правка работают для всех прошивок; сохранение — только для
> 32-битных Denso (SH7055/SH7058), у которых известен пересчёт контрольных сумм.

## Установка

**Готовая сборка** — в GitHub Releases (или артефакты GitHub Actions):

- Windows — `SubaruEcuEditor-<версия>-windows.zip`: распаковать и запустить `SubaruEcuEditor.exe`.
- macOS (только Apple Silicon) — `SubaruEcuEditor-<версия>-macos-arm64.dmg`. Приложение не
  подписано: первый запуск — правый клик → «Открыть» или
  `xattr -dr com.apple.quarantine /Applications/SubaruEcuEditor.app`.

**Из исходников** (Python 3.13):

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Дальше **File → Open ROM…** (Ctrl/Cmd+O), выбрать `.bin`/`.hex` и открыть карту в дереве.

## Возможности

### Редактор карт

- Дерево карт по категориям; каждая карта открывается в отдельном окне ОС, общее окно графика
  (**View → Graph Window**, Ctrl+G) следует за активной картой: 3D-меш или 2D-график. Клик по
  точке графика выделяет ячейку, клавиши шага в окне графика меняют выделенные значения.
- Правка ячеек и осей (двойной клик по заголовку), шаг клавишами `=` / `-` (с Control — мелкий
  шаг), Ctrl+C / Ctrl+V в формате Excel. В ячейке — значение, которое реально легло в ROM.
- **Checkpoint**: изменения относительно точки отсчёта обводятся (красный — больше, синий —
  меньше), в подсказке — было/стало. **Set checkpoint** ставит новую точку, **Откатить к
  checkpoint** возвращает карту (или все карты — меню **Карты**).
- Общие оси: если ось используют несколько таблиц, окно об этом предупреждает; правка оси
  меняет её у всех, значения других таблиц не пересчитываются (как в RomRaider).
- Справка о карте — ⓘ или F1: описание, формула, оси, адрес в ROM.
- **Maps → Ошибки и переключатели…** (Ctrl/Cmd+E) — включение/выключение DTC и OBD-переключателей.
- Клавиши переназначаются в **File → Settings…**.

### Единицы и язык

- **View → Единицы**: как в описаниях (psi, °F, mph) или метрические (bar, °C, km/h). Пересчёт
  только на экране, в ROM пишется ближайшее представимое значение.
- **View → Язык / Language**: русский или английский, применяется после перезапуска. Названия
  и описания карт из definitions не переводятся.

### Сохранение

**File → Save ROM** (Ctrl/Cmd+S) / **Save ROM As…**

- Первое сохранение за сессию всегда спрашивает путь (`<имя>-edited.hex`), чтобы не перезаписать
  стоковую прошивку.
- Контрольные суммы пересчитываются автоматически. Сохранить можно, только если суммы исходного
  файла сошлись при открытии; для 16-битных ЭБУ и части дизелей сохранение недоступно.
- Запись атомарная: оборванное сохранение не портит файл.

### Перенос карт

**Maps → Transfer Maps from ROM…** переносит выбранные таблицы из донорской прошивки в открытую
(например, карты Forester XT в STI того же поколения). Нужны одинаковые база описаний и процессор.
Если размеры осей разные, значения интерполируются; таблицы на общих осях пересчитываются.
Отчёт (Markdown) сохраняется рядом с прошивкой. Отмены нет — только переоткрыть файл.

### ИИ (MCP-сервер)

**ИИ → MCP-сервер для ИИ** запускает сервер на `http://127.0.0.1:8765/mcp`. Подключение Claude Code:

```bash
claude mcp add --transport http subaru-ecu http://127.0.0.1:8765/mcp
```

ИИ читает прошивку и карты, сравнивает с донорской прошивкой, анализирует логи RomRaider и
Car Scanner и **предлагает** правки — они пишутся в образ только после подтверждения в окне
с подсветкой изменений. Сохранить файл ИИ не может. **Заметки о прошивке** (ИИ → Заметки…)
хранят контекст между разговорами: машина, моды, что уже меняли.

### Логгер

**Логгер → Открыть логгер…** (Ctrl+L) — логгер через Tactrix OpenPort 2.0 (SSM по CAN, при
необходимости K-line). Альфа: проверен на эмуляторе и частично на машине.

- Выбор параметров с поиском, профили RomRaider (Cmd/Ctrl+P — быстрый выбор).
- Дашборд с плитками и графики за последние 30 с.
- Вкладка **«Ошибки»** — коды неисправностей из памяти ЭБУ (активные сейчас и сохранённые) и
  сброс памяти ошибок (reset ЭБУ). Сброс стирает и обученные значения (топливные коррекции, ХХ),
  и мониторы готовности, поэтому спрашивает подтверждение и недоступен во время записи лога.
- Запись в CSV формата RomRaider (`ecu-editor-logs/<прошивка>/` рядом с ROM) с отметками
  событий (пробел).
- При обрыве связи логгер сам переподключается (со сбросом адаптера) и продолжает запись в тот
  же файл: на время обрыва строк нет, первая строка после него — с отметкой 2. В строке
  состояния — число обрывов, время без связи и причина: «OpenPort не найден в USB» (кабель,
  порт, питание) или «адаптер на USB есть, но не отвечает» (завис сам адаптер). При неудачном
  подключении — такая же подсказка, что проверить.
- Диагностика: **«Журнал адаптера…»** открывает папку `logger_traces/` рядом с settings.ini.
  В ней побайтовый журнал обмена `trace_*.log` (что отправлено и что пришло, с временем) и
  `events.log` — подключения (в том числе неудачные), обрывы, каждая попытка переподключения
  с причиной, восстановление и необработанные исключения (включая фоновый поток опроса). Путь
  текущего trace-файла показывается в тексте ошибки обрыва.
- Пункт **«Эмулятор (без машины)»** — посмотреть окно без адаптера.

## Дополнительные definitions

Кроме `definitions/editor/ecu_defs.xml` читаются все `*.xml` из:

- `definitions/editor/extra/` в репозитории — свои находки;
- `definitions/editor/extra/` рядом с settings.ini (**Файл → Папка definitions…**) — свои файлы,
  например папка `ECUFlash/subaru standard` из [SubaruDefs](https://github.com/TD-D/SubaruDefs).

Поддерживаются форматы RomRaider и EcuFlash. Дополнения только добавляют новые таблицы и
помечаются в интерфейсе значком ⚠ как непроверенные. Изменения подхватываются после перезапуска.

## Настройки

`settings.ini` — `~/.config/subaru_ecu_editor/` (macOS/Linux) или `%APPDATA%\subaru_ecu_editor\`
(Windows): клавиши, последний ROM (открывается при запуске), окно графика, единицы, язык, MCP.
Рядом лежат заметки ИИ (`notes/`), свои профили логгера и журналы в `logger_traces/`:
побайтовый обмен с адаптером (`trace_*.log`) и события программы (`events.log` — подключение,
обрывы с причинами, необработанные исключения).

## Разработка

```bash
pytest           # тесты; интеграционные пропускаются без прошивок в ecu/
mypy main.py src # проверка типов
```

- `src/core` — модель без Qt, `src/presenters` — презентеры, `src/ui` — виджеты,
  `src/ai` — MCP-сервер, `src/logger` — логгер, `src/log_setup.py` — файл событий и перехват
  исключений. Подробнее об архитектуре — в `CLAUDE.md`.
- Строки интерфейса — `tr("…")` по-русски, перевод в `src/locale/en.py`.
- Сборка: `pip install pyinstaller && pyinstaller subaru_ecu_editor.spec`. Иконки в `assets/`
  генерируются из `icon.svg`.
- Версии — SemVer по git-тегам `vX.Y.Z`. Релиз: GitHub → Actions → **Release** → выбрать
  patch / minor / major; workflow соберёт Windows и macOS и создаст тег с GitHub Release.

## Ограничения

- Сохранение 16-битных ЭБУ и дизелей недоступно.
- На графике точки нельзя перетаскивать мышью: значения меняются клавишами шага или в таблице.
- Раздел Tools — заглушка.

## Предупреждение

Изменение калибровок ЭБУ может повредить двигатель и сделать поведение автомобиля опасным.
Описания RomRaider распространяются «как есть» — см. дисклеймер в `definitions/editor/ecu_defs.xml`.
