# Subaru ECU Editor

Десктопный редактор калибровочных карт прошивок (ROM) ЭБУ Subaru на Python + PyQt6
(графики — pyqtgraph, 3D — OpenGL).
Использует описания таблиц в формате RomRaider (`ecu_defs.xml`): по ним определяет,
какой ЭБУ в образе, находит карты (наддув, топливо, зажигание и т.д.) и показывает
их в табличном редакторе с осями в физических единицах.

> Статус: ранняя стадия. Чтение, редактирование и сохранение ROM работают; сохранение —
> только для 32-битных Denso (SH7055/SH7058), у которых известен пересчёт контрольных сумм.

## Быстрый старт

Требуется Python 3.13 (проверено на нём; нужен ≥ 3.10 из-за синтаксиса `X | None`).

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Дальше: **File → Open ROM…** (Ctrl/Cmd+O), выбрать `.bin`/`.hex`-образ и открыть карту
в дереве категорий — она откроется в отдельном окне.

## Возможности

- Автоопределение прошивки по `internalidaddress` / `internalidstring` и размеру файла.
- Наследование описаний RomRaider: child-описание (`<rom base="...">`) мержится
  поверх base-описания по имени таблицы.
- Чтение таблиц 1D / 2D / 3D, типов `uint8`, `int8`, `uint16`, `int16`, `uint32`,
  `float` в big/little endian. Для `float` атрибут `endian` инвертирован, как в
  RomRaider: все float в `ecu_defs.xml` (32-битные SH7055/SH7058) помечены
  `endian="little"`, а в ROM лежат big-endian. При записи ROM нужно упаковывать так же.
- Пересчёт raw → физические значения по `scaling expression` (безопасный eval:
  только арифметика и `x`).
- Запись правок в образ ROM в памяти (`EcuParser.rom_bytes`) — ячейки и оси из ROM:
  - целые до 16 бит: подбирается сырое значение, чей пересчёт ближе всего к введённому
    (перебором всех 256/65536 вариантов по `expression`); в ячейке показывается то,
    что реально легло в ROM. Если ближайшим оказалось текущее значение, берётся
    соседнее представимое в нужную сторону — мелкий шаг на грубой шкале не «застревает»;
  - `float` и `uint32` — по обратной формуле `to_byte`; целые ограничиваются диапазоном типа;
  - checkpoint каждой карты хранится, пока открыт ROM, и переживает переключение карт.
- Оси: из ROM или статические (`Static X/Y Axis`). Статические подписи показываются
  как в definition («1st», «Enable Above», «-40») и не редактируются.
- Деление на ноль в scaling (`96560.6/x` при x=0) даёт `inf`, как в RomRaider.
- Над деревом карт — открытая прошивка: имя файла и код прошивки с описанием ЭБУ
  («AZ1G301F · JDM Subaru Impreza STi 08 · SH7058»), в подсказке — полный путь и ECU ID.
- Оконный режим: главное окно — дерево карт, меню и статус; каждая открытая карта —
  отдельное окно ОС (можно разложить по мониторам), график — ещё одно окно:
  - фон карты в дереве — её уровень из definitions (`userlevel`): 1 — основные таблицы
    (синий) … 5 — служебные (красный), бледной шкалой; легенда с подсказками — над деревом;
  - карта, чьи значения или оси отличаются от её checkpoint, — жирная, с ● перед
    размерностью; её категория тоже жирная; отметка снимается, если вернуть значения
    или нажать Set checkpoint, и сбрасывается при открытии другого ROM;
  - в дереве рядом с именем — размерность карты 3D / 2D / 1D; в окне карты под именем —
    описание «3D · 18 × 13 · psi», «2D · 16 · RPM», «1D · RPM»;
  - клик или Enter по карте в дереве открывает её окно (или поднимает уже открытое) поверх
    остальных, не забирая фокус у дерева — можно листать и открывать дальше;
    Control+Enter закрывает окно карты;
  - новые окна встают лесенкой справа от главного и не выходят за экран;
  - checkpoint карты переживает закрытие её окна (пока открыт ROM); правка общей оси
    сразу видна в открытых окнах других карт на ней; перенос карт обновляет открытые окна;
  - открытие другого ROM закрывает все окна карт.
- Редактор (окно карты):
  - кнопка ⓘ рядом с названием (или F1) — справка о карте: описание из definitions (на
    английском, как в RomRaider; есть у всех карт AZ1G301F), категория и уровень, размерность,
    формула пересчёта, оси (диапазон, число точек, с какими таблицами общая), тип и адрес
    в ROM, считается ли сравнение по коду ЭБУ; окно немодальное — можно держать рядом;
  - вид по форме карты: 3D — таблица; 2D — всегда одна строка со многими столбцами
    (векторы, хранящиеся в ROM столбцом, показываются транспонированными; правки
    пишутся в ROM по исходным координатам); константа 1×1 — поле ввода с подписью
    (единицы измерения) в белой рамке по центру, с теми же клавишами шага и checkpoint;
  - фон ячеек окрашен по значению от минимума таблицы (синий) до максимума (красный) —
    той же шкалой, что меш и 2D-график, но светлее, чтобы текст читался; `inf` — серые;
    при правке шкала пересчитывается по новым min/max; выделение — нейтральный серый;
  - столбцы растягиваются по ширине, но не уже своего самого длинного значения —
    если места мало, появляется горизонтальная прокрутка;
  - заголовки осей из definition с единицами: «Engine Load, g/rev» над столбцами,
    «Engine Speed, RPM» — вертикально слева от строк;
  - правка ячеек (отрицательные числа, десятичная точка или запятая,
    отображение с 2 знаками);
  - шаговое изменение выделенных ячеек (в таблице, после выделения столбца/строки
    кликом по заголовку или в окне графика): клавиши «увеличить» /
    «уменьшить» (по умолчанию `=` и `-`, то есть +/− без Shift). Без модификаторов —
    крупный шаг, с зажатым Control (физический Ctrl и на macOS) — мелкий.
    Шаги подставляются из `fineincrement` / `coarseincrement` таблицы (не меньше 0.01)
    и правятся над таблицей;
  - клавиши переназначаются в **File → Settings…** (⌘, / Ctrl+,; на macOS пункт
    в меню приложения);
  - checkpoint: при открытии карты её значения и оси — точка отсчёта; кнопка
    **Set checkpoint** переустанавливает её на текущие. Ячейки и точки осей (в заголовках),
    изменённые относительно checkpoint, обводятся: красным — больше, синим — меньше.
    Правка общей оси подсвечивается и в других таблицах на ней, даже если их ещё
    не открывали; перенос карт тоже запоминает оси «до переноса»;
  - подсказка при наведении на изменённую ячейку (и на поле константы): значение
    checkpoint и изменение — «Checkpoint: 1600.00 / Изменение: +50.00 (+3.1%)»;
    у ячеек без изменений подсказки нет;
  - сравнение с checkpoint учитывает оси: если точку оси сдвинули, ячейка сравнивается
    с тем, что ЭБУ прочитал бы из старой карты в новой точке, а не со старым числом в той
    же клетке. Расчёт — дословно как в коде ЭБУ (разобран в AZ1G301F, `core/ecu_lookup.py`):
    линейно по X, затем по Y; за краями оси — крайнее значение; повтор точки оси — ступенька;
    интерполируются сырые числа, поэтому в картах с нелинейной формулой (AFR) результат
    отличается от линейного смешивания AFR. Этот код найден во всех 32-битных прошивках
    SH7055/SH7058 архива RomRaider (411 шт.); для остальных (16-битные, FA20DIT) — линейная
    интерполяция физических значений.
    Сдвиг оси 122 → 113 °F между 1500 и 1300 RPM: «было» = 1400, ячейка 1300 — синяя,
    в подсказке «Checkpoint: 1400.00 (по осям checkpoint; в ячейке было 1300.00)»;
  - правка значений осей двойным кликом по заголовку;
  - Ctrl+клик по заголовку (физический Control, на macOS тоже) выделяет саму точку оси,
    а не ячейки столбца/строки; можно выделить несколько точек одной оси. Точки
    подсвечиваются янтарным, клавиши шага меняют значения оси, поля шага показывают
    шаги оси из definition («Шаг оси»). Клик по ячейке или обычный клик по заголовку
    снимает выделение оси и возвращает шаги значений; Ctrl+C/V по заголовку работает
    с выделенными точками;
  - общие оси: если ось в ROM используют и другие таблицы, под заголовком карты
    показывается «⚠ Общая ось Y — ещё 18 таблиц», список — в подсказке. Правка такой оси
    меняет её и у них (байты оси одни), но их значения не пересчитываются — как в RomRaider;
  - Ctrl+C / Ctrl+V для выделения и для осей — TSV/CSV, совместимо с Excel.
    Размер вставки должен точно совпадать с выделением.
- Дерево карт с клавиатуры: стрелки — стандартная навигация; Enter на карте — открыть
  её окно, Control+Enter (физический Control, на macOS тоже) — закрыть; Enter на категории —
  раскрыть/свернуть.
- Окно графика — одно на все карты, следит за активным окном карты (при закрытии —
  за последним активным); **View → Graph Window**, Ctrl+G:
  - вид по форме таблицы: 3D — меш, 2D (одна строка или столбец) — обычный график,
    константа 1×1 — окно скрывается;
  - пока пункт меню включён, окно появляется само, когда у активной карты есть график, не
    забирая фокус; закрытие окна крестиком выключает пункт; клавиши шага в окне графика
    меняют активную карту;
  - при первом показе за сессию окно небольшое и встаёт под окном карты (не хватает места
    снизу — справа от него); дальше стоит, где его оставили; размер меняется свободно,
    подсказка по мыши — в значке ⓘ;
  - между запусками сохраняются включённость и размер окна (положение — нет).
- 2D-график (pyqtgraph):
  - по горизонтали — реальные значения оси, если она строго монотонна, иначе — точки
    через равные интервалы с подписями оси (статические оси: «Max Range A / Min Range B»);
  - точки цветом по значению, выделенные ячейки — белые с тёмной обводкой; `inf` — серые
    на уровне минимума, без линии;
  - клик по точке выделяет ячейку, Ctrl/⌘+клик — добавляет/снимает; колесо — масштаб,
    перетаскивание — сдвиг; масштаб сохраняется при правках и сбрасывается при смене
    карты или кнопкой «Сбросить вид».
- 3D-вид (pyqtgraph + OpenGL):
  - меш с цветом по значению (синий → красный);
  - подписи осей X/Y (название и диапазон) лежат в сцене вдоль своего ребра сетки
    и только поворачиваются вокруг него к камере; читаются слева направо, не зеркалятся;
  - позиции по X/Y берутся из реальных значений осей (если ось монотонна),
    иначе — равномерно по индексу;
  - меш перестраивается при правке ячеек, вставке и изменении осей;
    выделенные в таблице ячейки отмечаются белой точкой с тёмной обводкой
    и тонкой «ножкой» до пола (цвет меша не перекрывается); ячейки с `inf` — серые;
  - клик по узлу меша выделяет ячейку в таблице, Ctrl/⌘+клик — добавляет/снимает
    её в выделении;
  - мышь: перетаскивание ЛКМ — вращение, колесо — масштаб, СКМ — сдвиг; «Сбросить вид».

## Единицы

**View → Единицы**: «Как в описаниях (psi, °F, mph)» или «Метрические (bar, °C, km/h)» —
сразу для всех окон; выбор сохраняется (`[view] units`).

- Пересчитываются давление (psi → bar, 3 знака после точки), температура (°F → °C) и
  скорость (mph → km/h) — значения, оси, подписи, шаги клавишами, подсказки, буфер обмена.
  Единица определяется по последней части подписи в скобках: «Target Boost (psia)
  Compensation (%)» — проценты и не пересчитывается. Статические оси (подписи) — как есть.
- ROM, сессия и checkpoint остаются в единицах definitions; пересчёт — только на экране.
  Введённое значение переводится обратно и кодируется как обычно (ближайшее представимое):
  0.5 bar → 7.251 psi в ROM → на экране 0.500. Для нелинейных формул пересчёт встроен в
  формулу таблицы — расчёт ЭБУ в сырых числах и квантование остаются точными.
- В справке карты (ⓘ) — исходная формула из definitions и пометка, что пересчитано.

## Язык

**View → Язык / Language**: русский или английский — весь интерфейс целиком: меню, окна,
подсказки, сообщения, ошибки, отчёт переноса. Названия, категории и описания карт берутся
из definitions и остаются как есть (на английском). По умолчанию — язык системы (русский
для русской системы, иначе английский), выбор сохраняется (`[ui] language`). Язык
меняется после перезапуска: программа предлагает перезапуститься сразу (с обычным вопросом
о несохранённых правках).

Исходный язык строк — русский: в коде они обёрнуты в `tr("…")`, английский перевод лежит в
`src/locale/en.py`. Тест `tests/test_i18n.py` проверяет, что у каждой строки есть перевод с
теми же `{плейсхолдерами}` и что лишних переводов нет.

## Ошибки и переключатели

**Maps → Ошибки и переключатели…** (Ctrl/Cmd+E) — окно с плашками для таблиц `Switch` из
definitions: ошибки DTC (в AZ1G301F — 108) и переключатели OBD-II.

- Плашка — код ошибки, название, тумблер; описание — в подсказке. Состояние читается по
  байтам в ROM: включена (белая), выключена (тёплая), байты не совпали ни с одним вариантом
  (серая, менять нельзя). Изменённые с открытия файла — с оранжевой рамкой.
- Поиск по коду и названию (P013, O2, AVCS…), фильтр «Все / Выключенные / Изменённые»,
  счётчики. Переключение — правка ROM: отмечается как несохранённая и сохраняется вместе
  с пересчётом контрольных сумм.
- Выключенная ошибка не исправляет неисправность, а прячет её — об этом предупреждение в окне.

## Сохранение и контрольные суммы

**File → Save ROM** (Ctrl/Cmd+S) и **Save ROM As…** (Shift+Ctrl/Cmd+S).

- Первое сохранение за сессию всегда спрашивает путь и предлагает `<имя>-edited.hex`,
  чтобы случайно не перезаписать стоковую прошивку; дальше Save пишет в тот же файл.
- Перед записью пересчитываются контрольные суммы ЭБУ: таблица «Checksum Fix» из definitions
  (`0x7FB80` / `0xFFB80`), записи «начало, конец (включительно), сумма»; сумма 32-битных
  слов участка плюс записанное значение = `0x5AA5A55A`. Алгоритм проверен на архиве RomRaider:
  у стоковых файлов суммы сходятся в 405 из 409 32-битных прошивок с такой таблицей.
- Сохранять можно, только если при открытии суммы исходного файла сошлись: значит,
  алгоритм для этого ЭБУ подходит. Иначе (16-битные ЭБУ — таблицы сумм нет; дизели
  2009–2011 и Forester 2.5i AT 2011 — суммы не сходятся) сохранение отказывает с объяснением.
- Запись — через временный файл и замену: оборванная запись не портит файл. Меняются
  только правленые байты и записи контрольных сумм.
- Несохранённые правки отмечаются в заголовке окна; при закрытии программы или
  открытии другого ROM — вопрос «Сохранить / Не сохранять / Отмена».

## Перенос карт из другой прошивки

**Maps → Transfer Maps from ROM…** — перенос выбранных таблиц из донорской прошивки B
в открытую в редакторе прошивку A (например, карты Forester XT в ЭБУ STI того же поколения,
когда ЭБУ будет обслуживать мотор донора).

- **Совместимость:** переносить можно только при одинаковой корневой базе описаний
  (`16BITBASE` / `32BITBASE`, цепочка `base` разворачивается до конца) и одинаковом
  процессоре (`memmodel`: SH7055, SH7058, …). Иначе перенос не запускается.
- **Выбор:** общие по имени таблицы (у обеих есть адрес), дерево по категориям с
  галочками, фильтр, «Выбрать все» / «Снять все» (по видимым с учётом фильтра).
  Таблицы, которые нельзя перенести, показаны неактивными с причиной.
- **Правила** (размерность всегда остаётся как в A):
  - размер по оси совпадает — ось и значения B переносятся как есть;
  - размер отличается — ось A переписывается: первая и последняя точки из B,
    промежуточные пропорционально по индексам оси B (сохраняется распределение
    точек донора); значения — билинейная интерполяция из B;
  - статические оси (2D-списки параметров) — как есть, по порядку; при разном размере
    таблица недоступна;
  - общие оси A: если ось переписана, остальные таблицы на ней пересчитываются со своих
    старых значений на новую ось; общую ось двух выбранных таблиц задаёт первая;
  - значения пишутся в ближайшее представимое для типа A.
- **После переноса** изменённые таблицы подсвечиваются рамками checkpoint относительно
  состояния до переноса. Отмены нет — откатить можно, переоткрыв файл A.
- **Отчёт** (Markdown) сохраняется рядом с файлом A как
  `<имя A>.transfer-<дата_время>.md` и показывается в окне. В нём — что перенесено как есть,
  что интерполировано (с диапазонами осей до/после и максимальным отклонением от карты B
  в точках донора), что пересчитано из-за общих осей и что пропущено.

Большое отклонение — сигнал проверить карту глазами: при ужатии по оси резкие ступеньки
донора (например, 65 → 0 % в Max Wastegate Duty) сглаживаются.

## Настройки

Хранятся в INI-файле пользователя (`QSettings`, `IniFormat`):

- macOS / Linux — `~/.config/subaru_ecu_editor/settings.ini`
- Windows — `%APPDATA%\subaru_ecu_editor\settings.ini`

Что сохраняется:

- привязки клавиш (`[keys]`, в читаемом виде: `increase==`, `decrease=-`); битые
  или конфликтующие значения при чтении заменяются значениями по умолчанию;
- последний открытый ROM (`[session] last_rom`) — при запуске программа сразу открывает
  его. Если файл пропал, путь забывается, в статусе — сообщение;
- окно графика (`[graph] enabled`, `size`) — включён ли автопоказ и размер окна;
- единицы на экране (`[view] units`) и язык интерфейса (`[ui] language`).

Checkpoint и несохранённые правки ROM между запусками не сохраняются.

### Архитектура

MVP со слоем сценариев и Qt Model/View для таблиц:

- **Ядро** (`src/core`) — чистый Python + pydantic + numpy, от Qt не зависит, покрыто тестами.
  `RomSession` — сценарии над открытым ROM и всё его состояние (checkpoint, изменённые карты).
- **Presenter** (`MainPresenter`) — тонкая связка: подключается к окнам карт при их открытии
  (`EditorView.map_opened`), вызывает сценарии `RomSession`, показывает результат.
- **View** (`src/ui`) — виджеты и Qt-сигналы. Таблица карты — `MapTableModel` (числа, а не
  текст в ячейках) + `MapTableView` + делегат и заголовки.

### Как открывается ROM

1. `MainPresenter.open_rom` при первом вызове лениво загружает `EcuDefsRepository`
   из `definitions/ecu_defs.xml`.
2. `EcuDefsRepository.match` перебирает child-описания: сверяет `filesize` и строку
   `internalidstring` по адресу `internalidaddress`.
3. `resolve` мержит найденное child-описание с его base (рекурсивно).
4. `EcuParser.list_maps` отдаёт редактируемые таблицы (1D/2D/3D с адресом),
   отсортированные по категории и имени.
5. `EcuParser.load_table` читает матрицу (row-major: Y, затем X) и оси,
   применяет scaling и возвращает `CalibrationTable`.

## Ограничения и TODO

- **Сохранение 16-битных ЭБУ и дизелей** недоступно: пересчёт их контрольных сумм не известен.
- **Tools** — раздел-заглушка (планируется интерполятор и т.п.).
- В 3D-виде нельзя менять значения: подъём/опускание выделенных точек — следующий шаг.
- 1D всегда читаются как одно значение (1×1).
- При нескольких совпадениях definition берётся первое.
- Поле `format` из scaling игнорируется: 2 знака после точки, для bar — 3.

## Предупреждение

Изменение калибровок ЭБУ может повредить двигатель и сделать поведение автомобиля
опасным. Описания RomRaider распространяются «как есть» — см. дисклеймер в начале
`definitions/ecu_defs.xml`.
